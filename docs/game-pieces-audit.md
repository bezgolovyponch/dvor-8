# v0 — game pieces audit

Built 2026-10-12 at repository state `a191e0c`. This is the audit the creator asked for: every element, its
purpose, the path by which it reaches a metric, the model those paths compose, the visual and item design, and
then the best-evidenced techniques from game studies with **explicit, verified, doable** changes.

Every number here is **computed**, not typed. The lever table is generated by
`node tools/audit-report.mjs > docs/audit-levers.json`, and the figures below are read from that file. If a
number and the JSON ever disagree, the JSON is right.

---

# 1. Verdict, and the distinction that governs everything

The creator asked for the "main metrics influence rate of all those parts and the whole". That rate exists, and
it splits into two halves that must never be mixed:

| Half | Status | Why |
|---|---|---|
| **A part → a metric** | **`BENCHMARKED`** — reproducible accounting | The metric identities are filed definitions and the components are published. A change *here* has a computed effect with a t-statistic |
| **A part → the player's behaviour** | **`UNVERIFIED`** — no causal link exists | This is the design→engagement link. `docs/game-design-formula.md` §4 records the search: no study isolates a single design parameter and measures an engagement outcome |

**So this audit reports two different kinds of numbers, labelled apart:**

- **`ACCOUNTED`** — a rate read off the model. Deterministic, reproducible, verifiable by re-running the command.
- **`DESIGN`** — a direction with a citation, but **no measured rate**. Reported as a direction, never as a number.

**No suggestion in §7 is offered as a guaranteed metric increase unless it is `ACCOUNTED`.** Where a suggestion
carries a coefficient, it is a regression coefficient from a real study — which is an *association*, not a
guarantee, and is labelled as such.

# 2. The component inventory

20 modules, 100 exported symbols. Decomposed by the two verified formalisms: **atoms** (the project's own
`docs/structure.md` type system) and **node types** (Machinations: sources `S`, pools `P`, drains `D`,
converters `V`, traders `X`, gates `G`).

## 2.1 The scoring economy — the engine of every number the player sees

| Atom | Type | Machinations node | Parameter (from code) | Purpose | Path to a metric |
|---|---|---|---|---|---|
| a thing takes `hp` hits | rule | `P` pool | 25 kinds, hp 1–3 | makes effort visible | → session length |
| hitting it | input | `V` converter | `strike()` | the core verb | → session length |
| a combo multiplies | rule | `V` converter | window 2.5 s (5 s weed) | rewards a faster run | → **score rate** |
| the combo lapses | rule | `D` drain | `tick()` | makes the multiplier a decision | → score rate |
| score | state | `P` pool | `left() === 0` ends the yard | the run's readout | → share line |
| **nothing is taken on lapse** | rule | — | tested | keeps progress monotonic | → all retention |

**Purpose, stated as the metric it serves:** the combo is the only thing in the game that converts *speed* into
*score*. It is the sole driver of `score rate`, and therefore the only element behind the share line's number.

**A structural observation.** In Machinations terms this economy has **one source (nothing), one drain (score
never decreases, so effectively none), and one converter**. `docs/monetisation-playground.md` §4 found that the
revenue distribution differs sharply between ad-led and payer-led strategies. This is the *unmonetised* version
of that economy: **there is no pool that can be drained, which is why nothing in the game can be lost.**

## 2.2 The pacing economy — where natural stops come from

| Element | Parameter | Purpose | Metric path |
|---|---|---|---|
| a yard is cleared | `left(w) === 0` | **stop 1** | `NATURAL_STOP` → ad slot |
| arriving at a new yard | `street.js extend()` | **stop 2** | `NATURAL_STOP` → ad slot |
| the album / card moment | `record()` | **stop 3** | `NATURAL_STOP` → ad slot |
| restart | `restartBtn` | deliberately **NOT** a stop | protects P6, the one-tap clean yard |

**`ACCOUNTED`.** `impressions_per_DAU = sessions × min(stops, floor(play_minutes / pacing))`. At the median
session (5.5 min) and 3-minute pacing, **2 slots fit and 3 are offered**, so the third stop is unreachable:
`6.875` impressions/DAU. At 8.5 min, `10.625`.

## 2.3 The mode economy — the only competitive differentiation

| Mode | thing | flight | damage | scatter | splash | chain | cooldown | combo | focus |
|---|---|---|---|---|---|---|---|---|---|
| sober | камень | 0.11 | 1 | 0 | 0 | 0 | 0 | 2.5 | sharp |
| weed | тапок | 0.34 | 1 | 0 | 0 | **2** | 0 | **5** | 0.42 soft |
| alcohol | бутылка | 0.16 | 1 | **10** | **22** | 0 | 0 | 2.5 | **0** soft |
| depression | кирпич | 0.30 | **3** | 0 | 0 | 0 | **0.7** | 2.5 | 0.20 dark |

**Purpose:** each mode is a different answer to "power or precision". Four independent 1–2 parameter changes,
each verified by test to alter **both** the throw and the focus.

**Metric path:** mode choice → `session length` (depression measured 47.3 s against 10–19 s in the audit's
playthrough) → `NATURAL_STOP` count → ad slots. **`DESIGN`** — no source measures the effect of a difficulty
mode on session length.

# 3. The overall model

The mechanics compose into one model with four layers. Only the bottom two are verifiable.

```
LAYER 4  RETENTION      D1, D7            <- NO verified design->retention link exists
   ^                                       (asserted by industry, never measured)
LAYER 3  ENGAGEMENT     sessions/day, session length, natural stops
   ^                     <- DVOR-8's design sets these; the SETTING is a CHOICE
LAYER 2  REVENUE        ARPDAU = ad + IAP  <- FILED identities
   ^                     LTV    = ARPDAU x lifetime
LAYER 1  ACCOUNTING     ARPDAU_ad = (eCPM/1000) x fill x impressions/DAU   <- published formula
```

**What the model says.** LTV is the product of an accounting layer that is exactly computable and an engagement
layer that is set by design and unmeasured. **Everything above Layer 2 is a design bet, not a calculation.**

**The composition, as one expression:**

```
LTV  =  [ (eCPM/1000) × fill × sessions × min(stops, floor(minutes/pacing))     +  ARPPU × payerShare ]
        ×  Σ_{d=1..H} D1 · d^(ln(D7/D1)/ln 7)

        └──────────── ACCOUNTED: every term is published or computed ────────────┘
        └─ DESIGN: sessions, minutes, stops, D1, D7 are all set by the game ─────┘
```

# 4. The metric influence rate — `ACCOUNTED` only

Read from `docs/audit-levers.json`. Paired on identical seeds, n = 20,000, 5 seeds.

| Lever the DESIGN can move | LTV effect | t | Verdict |
|---|---|---|---|
| **retention median → top quartile** (D1 and D7 together) | **×1.59** | 146.1 | the largest real lever |
| sessions/day 3.75 → 5.45 | ×1.45 | 121.4 | a design consequence, not a knob |
| session 5.5 → 8.5 min | ×1.39 | 132.9 | the second largest; **session length dominates** |
| eCPM rewarded Android → iOS | ×1.36 | 100.9 | **not a design lever** — platform mix |
| stops 3 → 6 | ×1.04 | 8.6 | small, and *not* zero (see §5) |
| ad-only → ad + a payer layer | ×51.6 | 101.1 | **UPPER BOUND ONLY — do not use** |

**On that last row.** A ×51.6 looks like the obvious answer and it is an artifact: the payer parameters
(`ARPPU_day $39.50`, payer share 0.0338) come from a **social-casino** filing, not a casual game. Feeding them
into a casual profile mixes two markets. The honest use is direction only: *a payer layer is worth far more
than ads, and this model cannot size it for this game.*

**The `ACCOUNTED` conclusion.** Retention is the biggest lever (×1.59), session length is second (×1.39), and
**neither is directly controllable** — both are outcomes of design choices the project has not measured.

# 5. Two corrections this audit forced on its own engine

Both were found by testing a claim rather than trusting it.

**1. Ads are discrete, and the cap was fractional.** `impressionsPerDau` used
`min(stops, play_minutes/pacing)`. A long session got a *fractional* allowance — 10.95 min ÷ 3 = 3.65 slots —
which **exceeded the 3 stops the design provides**, leaking ad revenue the game could never show, and leaking
more as `stops` rose. Fixed with a floor. This was the overstuffing the cap exists to prevent, hiding in the
tail of the engagement distribution.

**2. The anti-overstuffing claim was true on average and false as stated.** With the floor in place, **1,583 of
20,000 players (7.9%) run sessions past 9 minutes**, where extra stops genuinely do buy extra impressions. So
"asking for 8 stops instead of 3 buys nothing" is **false as a general statement** and true as an average. The
measured slope is **×1.04**.

**And a third, from the retention lever.** D1 and D7 are **one lever, not two**: `retention()` derives the decay
exponent from both, so raising D1 while holding D7 makes the curve *steeper*. Measured: the median curve gives
a lifetime of **8.84 d**, the top-quartile curve **12.16 d**, and the top quartile's D1 with the median's D7 —
which is what "raise D1" looks like on its own — gives **2.00 d**. That is a fall of **77%, not 23%**; an
earlier version of this line printed 23%, which is 2.0 as a share OF 8.8 rather than the fall from it. A
"better D1" can mean a much worse game, and the retention figure goes UP while it happens. Guarded by
`CURVE_INCOHERENT` and tested.

# 6. Visual and item design, and what it does to metrics

| Element | Parameter | Verified finding | Metric |
|---|---|---|---|
| picture size | 192×256 | Torralba 2009: 32×32 already gives 80% object reporting. 192×256 is ~48× that budget | `BENCHMARKED` — resolution is not the binding constraint |
| palette | 28 colours **from the photograph** | tested: a red car stays red, a blue car blue, a green tree green | `PROVEN` internally |
| the recognition cliff | — | Gruber 2021: 80% → 24% on one further reduction. The build sits far above it | `BENCHMARKED` |
| pixel-art restyle | — | **Bao 2023 found pixelation "did not have a big impact on emotions"** and shifted judgement toward *"an earlier period"* | **`DESIGN` — and it argues the restyle is a *novelty* effect, not a comprehension effect** |
| feedback (pause/kick/flash) | `HIT_PAUSE .03`, `BREAK_PAUSE .09`, `SHAKE_MAX 7` | Kao 2020, N=3018: partial η² **.003–.01**, under 1% of variance | `BENCHMARKED` as direction, **tiny** as effect |
| feedback amplification | — | Kao et al. 2024, n=1699: **amplification unexpectedly REDUCED motives** | **`DESIGN` — more is not better, measured** |
| hitstop | `BREAK_PAUSE 90 ms` | shipped-game data exists (8–15 frames for a 15% hit) | the build sits in a plausible band |
| screen shake | `SHAKE_MAX 7` | **no published parameter values anywhere** | `CHOICE`, honestly labelled |
| item hp | 1–3 | **no published equivalent** | `CHOICE` |

**The most useful visual finding is a negative one.** Bao's result means the 8-bit restyle **does not measurably
improve comprehension or emotional response**. Its verified effect is on *perceived time period*. So the
restyle's justification cannot be "it makes the yard more readable" — the defamiliarisation constraint in
`docs/constraints.md` P3 claimed exactly that, and it is not supported. What is supported is that the restyle
makes the yard read as **past**, which is a different and weaker claim.

# 7. Suggestions — explicit, verified, doable

Ordered by (confidence × size) ÷ cost. Each names its metric, its evidence class, and its expected effect.

## S1 — Move the retention curve, and measure it. `DESIGN` direction, `ACCOUNTED` size

**Do:** get the game played by 5–10 people (`docs/feasibility.md` stage 1), then measure D1 and D7.
**Why:** it is the largest lever in the whole model — **×1.59 on LTV (t=146)** — and it is the only one not yet
measured in any form.
**Verification:** `node tools/audit-report.mjs` reproduces ×1.59. The *design* that moves it is unmeasured, and
that is exactly why stage 1 exists.
**Cost:** a week. **This is the highest-value action available and it is not code.**

## S2 — Lengthen the session, because session length beats stop count. `ACCOUNTED`

**Do:** make one yard take longer to clear rather than adding more yards.
**Why:** `ACCOUNTED` — **5.5 → 8.5 min is ×1.39 (t=133)**, against **×1.04 for 3 → 6 stops (t=8.6)**. The
evidence says the lever is time-in-session, not stop-density.
**Verification:** the lever table.
**Cost:** a design change to `TARGETS` hp or `MAX_TARGETS`; testable against the existing suite.

## S3 — Do not add stops beyond what pacing allows. `ACCOUNTED`

**Do:** keep 3 stops at a 5.5-minute session. Adding more buys ×1.04 at most, and only for the 7.9% of players
whose sessions exceed 9 minutes.
**Why:** measured. The player-visible cost of a fourth stop is real; the revenue is 4%.
**Verification:** §5.
**Cost:** zero — it is a decision *not* to add.

## S4 — Install the intermediate investigate state. `DESIGN`, from a proven module

**Do:** add a fourth branch to the `folk` FSM: a person who half-saw something **walks toward the spot** instead
of the run ending.
**Why:** it is the only `GAP` in the reconstruction. Every proven comparable has it — Splinter Cell: Blacklist
uses a percentage threshold on the detection bar before investigating (Game AI Pro 2 ch. 28), MGS2 runs four
phases, AC2 escalates through search.
**Verification (doable):** a test that someone who half-saw walks toward the last-seen point and returns to `go`
after `GIVE_UP` with no further looking; plus a fairness test that a run cannot end from a single look.
**Cost:** one FSM branch. **Highest value per line of code in this audit.**

## S5 — Grade vision by distance. `DESIGN`, from a proven module

**Do:** multiply the per-person `rate` by a distance factor (Game AI Pro 2 ch. 4: certainty 1.0 / 0.7 / 0.5 /
0.4 / 0.3 by zone).
**Why:** today "a look" is one rate, so *where you stand* does not matter. Grading makes hiding a skill rather
than a button, which is what makes the loss `caused` rather than `imposed` (the revised PS2 rule).
**Verification:** a test that the danger rate at the near zone exceeds the far zone, and that hiding at the far
edge is safe.
**Cost:** one term in the rate.

## S6 — Stop claiming the restyle improves readability. `DESIGN` correction

**Do:** reword `docs/constraints.md` P3 and any player-facing claim. The supported statement is that the restyle
makes the yard read as *past*, and that resolution is not the constraint.
**Why:** Bao 2023 found no emotional or comprehension effect; the temporal-shift finding is what is real.
**Cost:** documentation, and it removes an unsupportable claim.

## S7 — Do not chase feedback amplification. `DESIGN`, measured negative

**Do:** hold `SHAKE_MAX`, `HIT_PAUSE` and `BREAK_PAUSE` where they are.
**Why:** Kao et al. 2024 (n=1699, pre-registered) found **amplification unexpectedly reduced motives**, and Kao
2020 found all juiciness effects under 1% of variance.
**Verification:** both sources, and the existing test *"many wrecks at once do not shake the picture off the
screen"*.
**Cost:** zero — another decision not to act.

## S8 — Prefer preference-matched rewards over variable schedules. `DESIGN`, strongest causal evidence

**Do:** if a reward or unlock system is ever added, match it to the player's stated preference rather than
randomising it.
**Why:** Nagle et al. 2014, N=210, the only controlled manipulation in this literature: preference-match
**η²p = .205** on enjoyment, while variable-ratio vs fixed-ratio was **not significant (η²p = .004)**.
**Cost:** only relevant if such a system is added. Recorded so the folklore does not win by default.

## S9 — Fix the source errors the audit found. `ACCOUNTED`

**Do:** the defects in `docs/constraints.md` §4 (Kao's DOI, the unsourced hit-pause and shake numbers, the
loss-aversion "2×", the 66-day habit figure, Zeigarnik, Swink's wording, the PXI author list, and the `news.js`
wiring), plus the two claims this audit withdrew from `docs/style.md`/`constraints.md` — the "gravity well above
Earth's" line and the restyle-improves-readability line.
**Why:** each is a claim in the tree that no source supports.
**Cost:** small. **Prerequisite for everything else being trustworthy.**

## S10 — What NOT to do

| Do not | Because |
|---|---|
| Add a payer layer on this model's numbers | the ×51.6 is a cross-market artifact |
| Add daily streaks | Fate/Grand Order ships cumulative *alongside* consecutive; the Waterloo study documents streak-harm |
| Claim retention improvement from album, days or the share line | no controlled measurement exists for any of them |
| Add more stops for revenue | ×1.04 |
| Build the live-news module as a differentiator | no comparable exists in either direction |
| Cite MGS or GTA alert timers | folklore; no publisher numbers exist |
