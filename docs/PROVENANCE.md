# PROVENANCE — what the app runs, and where it comes from

The question this file answers: *does the app rely on an external, real product, or on code we wrote ourselves?* It
depends on which half, and the answer is different for each. Everything below is a sha256 the tools recompute — none of
it is a claim.

## The converter: the OPERATOR'S OWN CODE, byte for byte

| step | artefact | sha256 | how it is verified |
|---|---|---|---|
| 1 | `/Users/m/Downloads/DVOR-8 Photo2Pixel v13.dc.html` — the operator's file (Claude Design output, 132 005 chars, dated 18 Oct 15:13) | `c5715724621be34e…` | it is the file `tools/v13/refs.mjs` reads; it is **not** produced by this repository |
| 2 | the engine class sliced out of it: `class Component extends DCLogic { … }` (115 511 chars) | `ea0273fee448126e…` | `tools/v13/refs.mjs` re-slices the HTML on every run and **refuses to continue** if the committed extraction differs |
| 3 | `tools/v13/engine-v13.txt` — the committed extraction | `ea0273fee448126e…` | same sha as step 2; git history: introduced at `3aaed44` (T+122) from the operator's file |
| 4 | `src/ref/engine.js` — the app's module, generated by `tools/v13/make-module.mjs` | `9f91d1ae87d7…` | `tools/engine-check.mjs` line **1b**: the module's body (115 478 chars) is **byte-identical** to the extraction; the only differences are the class header (`extends DCLogic` removed) and the line `export { Component };` |
| 5 | the app runs it: `src/ref/convert.js` imports `./engine.js`; `src/main.js` imports `./ref/convert.js` | — | `tools/engine-check.mjs` lines 2–4: it runs in a page (147 456 px, no errors), reproduces the operator's **FNV `7204df6f`** on the judged photo, and reports the operator's own stage numbers (**palette 12, windows 1321, tower 10×11/1262, checker 6×7/228**) |

**So the converter is not our code.** It is the operator's engine, extracted, hashed, embedded with a one-line wrapper,
and gated to be byte-equal to the extraction; the gate is chain step **0d ENGINE**, so a divergence stops the build.

There is no npm dependency and no third-party runtime package in this path: the app loads one ES module that is the
operator's class, and the wrapper. (The extraction is committed because the operator's `.dc.html` lives in `~/Downloads`
and is not part of the repository — if the operator's file moves, `refs.mjs` withholds the reference instead of silently
re-basing it, and `engine-check` refuses a module that no longer matches the committed extraction.)

## The annotation: the product's own gesture, our code

`src/pieces/region-grow.js` (tap → the connected region → its quad) and `src/pieces/scene-annotation.js` (the
reference's S7 contract: `{gy, h0, buildings:[{quad, clip, kind}], cars:[{box, view}]}`) are **our code**, written for
this app, each with its own check (6/6 and 6/6). They produce the *input* the reference is given by its author; the
conversion after that is the operator's engine.

## The game: ours

`src/main.js`, `src/world.js`, `src/render.js`, the HUD, the weapons, the news, the disasters, the vector fallback
route, and the eight other bricks are this repository's own code. They are the product around the operator's converter.

## External published *methods* the engine cites (and we did not import)

The engine's SPEC names its sources per stage — Heckbert 1982 (popularity quantisation) and Heckbert 1989 (homography),
Otsu 1979, Niblack 1986, Adams & Bischof 1994 (seeded growth), GrabCut (Rother 2004), ICM (Besag 1986), Bayer 1973,
Perlin 1985, Sobel & Feldman 1968, Serra 1982, Porter & Duff 1984 — and this repository's own bricks cite the published
sources they implement (PixelOE's selection rule, morphological closing, connected components). **These are methods, not
imported products**; the only imported product is the operator's engine.

## The honest limits

- The engine's *exactness* rests on the operator's file; if the operator publishes a newer version, this app is one
  extraction behind until `refs.mjs` is re-run and the module regenerated (the gate prints both shas so it cannot drift
  silently).
- The app's **frame** is the operator's; the app's **annotation** for a new photograph is ours (the tap), and its
  quality is the tap's quality — a grown quad is coarser than a hand-drawn one (measured: 12×23/153 panes from a tap
  against 10×11/1262 from the operator's own quad).
